## 0. 任务目标与验收标准

### 目标
1. 下单时不再选择送达地址，不再采集经纬度。
2. 订单详情、看护者工作台的地址固定显示**商家地址**。
3. 「确认接收」只剩三重校验：权限 + 在岗 + 状态 + 4 位交接码。

## 1. 铁律：以下内容禁止误删

| 对象 | 原因 |
|---|---|
| `delivery_time_wsh`、`pickup_time_wsh` | **时间字段，不是地点**。参与 `quoteOrder` 的 day/boarding/slot 三分支计算、`validateFulfillmentWindow`、`ensureNoPetIntervalConflict`。删了计价与档期全崩 |
| `receiver_available_start_wsh` / `_end_wsh` | 看护者接收等待窗口（end = delivery_time + 30min），被 `KeeperOrdersTab:36` 展示 |
| `frontend/src/components/common/AmapAddressPicker.vue` | **禁止删除组件**。`views/user/Addresses.vue:100`、`views/user/Merchants.vue:217` 仍在用 |
| `attendanceRadiusMeters`（签到半径） | 属于**考勤**功能，与 handover 无关，保留 |
| `GeoDistanceUtils`（`pet-common`） | 考勤、商家距离排序等多处使用，**禁止删除工具类** |
| `received_at_wsh` | 接收时间戳，审计必需，保留 |

## 9. 已知风险与残留

| 风险 | 等级 | 说明 |
|---|---|---|
| **交接码仅 4 位** | 高 | `generateHandoverCode()` 用 `%04d`，10000 种可能。原设计靠「码 + 距离」双保险，删掉距离后只剩「码 + 在岗」。理论上客户把码念给不在现场的看护者即可完成交接。已确认本次**不补替代校验**，需业务侧知情 |
| 存量订单 | 低 | 列保留不 DROP，历史数据可正常读；老订单不再触发「未记录送达坐标」400，反而解决了原有的卡死问题 |
| 快照取证 | 低 | 商家地址在 `merchantSnapshot` 中完整保留，纠纷取证链不断 |
| `received_*` 审计字段 | 中 | 删掉后无法再追溯「实际在哪接收」，只剩 `received_at` 时间戳。若业务需要留痕，应改为记录商家地址文本 |
| 前端旧缓存 | 低 | 老版本前端仍会提交坐标字段，后端删字段后 Jackson 默认忽略未知字段，不报错 |
| 看护者端地址显示 | 中 | 若列表转换器未填 `merchant_address_wsh`，会显示 `-`（见 §5 重要确认项） |
