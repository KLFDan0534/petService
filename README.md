> **两个进度文件别搞混**：`理解路线.md` 的恢复卡 = 精确到「读到哪个文件第几行」；`PROGRESS.md` = 这次会话做了什么、有什么结论。**恢复优先看恢复卡。**

## 💬 三条提示词（直接复制）

### ① 开始工作：恢复上次进度

```
请先按顺序读取：
1. a理解与进度/理解路线.md 顶部的「⚡ 恢复卡」和「链路清单与断点」
2. a理解与进度/PROGRESS.md
3. 根目录 README.md、docs/index.md

核对当前代码和上次记录是否一致，然后告诉我：
1. 上次具体进行到哪里（精确到链路和文件）。
2. 已经确认了哪些事实。
3. 还有什么问题没有解决。
4. 我现在应该执行的第一个具体动作。

不要重新分析整个项目，不要修改代码，也不要一次安排多个任务。
如果进度文件不存在或记录不完整，请明确告诉我缺少什么，不要猜测上次的进度。
如果恢复卡和 PROGRESS.md 的日期对不上，先指出冲突再问我要以哪个为准。
```

### ② 工作中：只研究一个问题

```
我们现在只研究一个问题：<把你卡住的那句话写在这里>。

请结合当前项目的实际代码：
1. 找出相关的文件、类和方法。
2. 追踪调用顺序，说明数据在哪里发生变化。
3. 解释当前实现的目的和潜在问题。
4. 区分已经确认的事实与需要运行验证的推测。

先不要修改代码，也不要直接重构整个模块。
讲解完成后，只问我一个问题，检查我是否真正理解当前的执行过程。
```

> 用法示例：`我们现在只研究一个问题：通知创建后，未读数缓存是如何更新或失效的。`

### ③ 推进一条业务链路（理解主线专用）

```
我们按 a理解与进度/理解路线.md 推进下一条链路：<链路名，例：下单>。

请先读 a理解与进度/理解路线.md 第 4 节的"四步读法"，然后：
1. 告诉我这条链路的入口文件和方法，精确到 文件:行。
2. 只读这一条链路涉及的文件，不要扩散到其他模块。
3. 讲完之后，按第 4 节固定的 3 个问题提问，一次只问一个。
4. 全程不要修改代码。

如果这条链路需要的文件超过 8 个，先告诉我，我们拆成两轮。
```

### ④ 准备中断：保存现场

```
我现在要中断当前工作。请不要继续扩展任务，也不要擅自修改其他代码。
请根据本轮实际完成的工作，更新 a理解与进度/PROGRESS.md。
如果你无法直接编辑文件，就输出一份完整的更新内容供我保存。

必须记录：
- 本轮完成了什么。
- 实际检查过哪些文件和方法。
- 已经确认的结论，以及尚未确认的猜测。
- 已修改的文件、测试执行情况和当前工作区的重要状态。
- 下次回来后，第一个具体操作是什么。
- 目前明确不应该做什么。

下一步必须具体到文件、方法或验证命令，不能只写"继续学习某某模块"。
如果本轮没有取得进展，也请如实记录，不要编造成果。
```

## 📁 文件放哪（防止再乱）

| 写什么 | 放哪 | 命名 |
|---|---|---|
| 进度 / 下一步 | `a理解与进度/PROGRESS.md` | 固定 |
| 某个模块的业务链路 | `docs/` 根 | `<模块>讲解.md` / `<模块>速查.md` |
| 待修 bug | 追加到 `docs/BUGFIX清单.md` | `N<n>` / `X<n>` |
| 一次性排查记录、临时脚本、导出文件 | 新建 `docs/archive/<年>-<月>/` 再放 | **不要放根目录** |
| 接口 / 数据库设计 | `docs/api/`、`docs/database/` | 沿用现有编号 |

**根目录只允许放**：`README.md`、`pom.xml`、`docker-compose*.yml`、`start-*.bat`、`AGENT_RULES.md`。
**进度与理解类文档统一放** `a理解与进度/`（a 开头 = 资源管理器置顶）。

## ⚠️ 三条硬规矩

1. **一次只修一个 bug**，改完验证再下一个。不要一次给我 10 条 diff。
2. **改代码前先看 `git status`**。这个项目有别的 AI 工具会并发改文件甚至回滚分支。
3. **`docs/` 被 `.gitignore` 忽略**（第 48 行），换电脑前记得手动备份，否则文档全丢。
