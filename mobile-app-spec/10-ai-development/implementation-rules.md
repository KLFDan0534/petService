# Implementation Rules（实现规则）

## AI 开发原则

不要擅自设计新 UI · 不要修改设计语言 · 不要创造新颜色/间距/圆角 · 不要绕过 Token · 不要复制 API 逻辑 · 不要在页面直接写网络请求 · 不要把业务逻辑写进 UI · 不要重复实现组件。

优先级：复用组件 > Design Token > 已有 API > 页面规范 > 角色权限。冲突时：安全 > 状态机 > 权限 > 视觉。

## 默认规则（规格未覆盖时）

| 情况 | 默认行为 |
|---|---|
| 未规定动画 | 无动画（不添加） |
| 未规定间距 | 用最近的 spacing Token |
| 未规定状态 Badge 类别 | neutral |
| 未规定端点动词 | 按语义：查 GET / 建 POST / 改 PUT / 删 DELETE，联调校正 |
| 未规定空态文案 | 「暂无数据」+ 上下文引导 |
| 未规定错误处理 | 走 errors.md 决策树 |
| 列表是否分页 | 是（pagination.md） |
| 是否需要确认弹窗 | 资金/删除/审核/取消类一律确认 |
| 角色是否可见 | role-matrix 无记载 → 不可见（保守） |

## 一致性守则

- 同一语义组件跨页面必须同一实现（如 StatusBadge 全局唯一）
- 同一数据跨页面展示格式一致（金额/时间/状态文案）
- 命名对齐 00-overview/terminology.md

## 变更记录纪律

- 对规格的偏离/后端契约差异：在 99-reference/conflicts.md 追加条目（现象/规格值/实际值/裁决）
- 不可确认点：unresolved.md 追加，禁止自行编造
