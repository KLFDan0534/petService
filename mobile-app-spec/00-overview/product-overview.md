# Product Overview

（来源：`PRODUCT.md` EXISTING + 页面归纳 DERIVED）

## 产品定位

宠物服务与寄养管理平台。连接宠物主人与商家/寄养师，支持订单履约与支付，并为运营者提供审核、争议处理与平台监控工具。

## 目标用户（EXISTING）

宠物主人、商家、寄养师、客服、管理员。用户都在快速完成操作型任务：浏览服务、下单追踪、管理宠物、审核申请、处理客服、监控平台。

## 品牌个性（EXISTING）

**Practical, trustworthy, warm**（实用、可信、温暖）。界面要足够可靠以支撑操作型工作，同时对宠物主人保持友好。

## 反面参考（EXISTING，禁止出现）

- 装饰性仪表盘
- 过度饱和的橙色大面积色块
- 任务型界面里出现营销式 Hero 大版式
- 低对比度着色文字
- 状态标签/表格数据使用不安全 HTML 渲染

## 设计原则（EXISTING，继承为 App 原则）

1. **任务清晰优先**：控件、列表、表单优先服务扫读与操作。
2. **一致性建立信任**：状态、按钮、列表、布局模式跨角色行为一致。
3. **温暖但克制**：亲和力来自文案与细节，不靠重色块。
4. **默认安全**：用户/API 内容一律按文本渲染，除非显式结构化。
5. **可及的操作**：重要状态与操作在明暗主题下均可读、可见焦点、可操作。

## 核心用户旅程（DERIVED，详见 05-business/workflows.md）

```
主人：注册→建档(宠物/地址)→浏览服务→下单(优惠券)→支付→等待送达→服务中(日报/聊天)→验收→评价
寄养师：申请资质→审核通过→接单/拒单→配送→开始(上传照片)→服务中(日报/考勤)→完成→收小费
商家：入驻审核→上架服务→接单派单→审核寄养师/客服申请→经营统计→提现
客服：工作台→会话/工单/投诉受理→处理→关闭
管理员：入驻/资质/内容/实名审核→订单退款仲裁→财务(钱包/提现)→运营(公告/Banner/优惠券)
```

## App 信息架构（DERIVED，来自 Web 导航）

- 首页 Dashboard：Banner、服务宫格、推荐、公告
- 5 Tab 底部导航 [PLATFORM]：首页 / 服务 / 宠物 / 订单 / 我的
- 我的：钱包、优惠券、会员、收藏、地址、评价、售后(退款/投诉/工单)、通知、客服申请、AI 助手
- 角色工作台按角色动态出现（寄养师工作台/商家工作台/客服中心/管理后台）
