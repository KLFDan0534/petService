# Development Plan（开发计划）

## 范围基线

- 移动端 App（Android 优先，iOS 按平台层映射）
- 后端契约冻结：消费既有 `/api`，不改后端
- 设计语言：Warm Editorial（01-design-system 为唯一视觉依据）

## 里程碑（对应 implementation-order.md）

| 里程碑 | 内容 | 退出标准 |
|---|---|---|
| M1 基础 | 工程+主题+网络+存储 | 主题双模式、Token 全量、模拟登录跑通 |
| M2 认证 | 登录/注册/找回/守卫 | 真机登录→刷新→登出闭环 |
| M3 C 端核心 | 首页/服务/详情/下单/支付/订单 | 下单支付全流程真机通过 |
| M4 沟通与售后 | IM/AI/通知/评价/退款/钱包/收藏/券/会员 | SSE 实时可用；售后闭环 |
| M5 角色工作台 | 寄养师/商家/客服/管理 | 各角色核心操作可用 |
| M6 打磨 | 动效/无障碍/暗色/离线/深链 | 验收清单全过 |
| M7 测试与发布 | 测试/性能/打包 | 见 testing.md |

## 人力/排期假设（RECOMMENDATION）

1-2 名 Android，约 8-10 周（M1 1周 · M2 1周 · M3 2-3周 · M4 2周 · M5 2周 · M6-M7 1-2周）。

## 风险

| 风险 | 缓解 |
|---|---|
| 响应字段与 data-models 推导不符 | 联调期以真实响应修正 DTO（记录 conflicts.md 模式） |
| SSE 在弱网/后台稳定性 | 轮询兜底 [E] 已内置；推送兜底后置 |
| 管理端表格复杂 | 移动端范围已裁剪（page-020） |
| 支付渠道未定（Web 仅钱包） | M3 先钱包支付；渠道接入单列任务 |
